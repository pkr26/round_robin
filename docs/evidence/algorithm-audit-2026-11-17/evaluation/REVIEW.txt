ALGORITHM AUDIT: EVALUATION AND OPTIONAL VISUAL DISCUSSION
Audit date: 2026-11-17 (user timezone America/Phoenix)
Scope: experiments/*.py; visual/{reviews,iterations,jobs,service,schemas}.py;
supporting edit/review packet paths in worker/image_tasks.py, providers/images.py
and api/visual.py. Product source was not changed.

Verdict
The bookkeeping and resource controls are substantial, but they are not evidence
that multi-agent discussion improves decision accuracy. The fixed-evidence study
executes a separate workflow from the production controller, and the optional
visual loop loses selected critic findings before generating an edit. New probes
reproduce four gaps despite 133 existing focused tests passing.

FINDINGS

EVAL-01 [P1, correctness] Selected visual findings never reach the editor.
Source: backend/src/round_robin/api/visual.py:356-374;
backend/src/round_robin/worker/image_tasks.py:218-248;
backend/src/round_robin/providers/images.py:255.
Trigger: approve an edit with intent "Address the selected finding" and a mapping
of findings to address/decline. The API saves the mapping, but _packet emits only
the free-text intent, brief and parent pixels. It omits finding IDs, observations,
regions, severities and dispositions. HTTPImageProvider.submit likewise only
serializes the brief and intent. Critic-selected feedback has no causal path to
generation unless the user manually repeats it in the intent. Declines have no
effect on the generated edit either. A paid edit can therefore ignore the exact
review findings it appears to act on.
Validation: probe.py::edit_packet_loses_dispositions; result saved in JSON.
Fix direction: construct and hash an immutable edit bundle resolving approved
parent finding IDs to observations, regions, requested changes, preserve rules
and explicit declines; transmit that exact bundle to the editor and re-reviewers.

EVAL-02 [P2, evaluation validity] The study does not execute the production
correction/re-audit protocol it could be used to justify.
Source: experiments/study_runner.py:545-578 versus production
backend/src/round_robin/orchestration/controller.py:335.
Trigger: a valid final audit rejects synthesis while allowance remains. Production
can reserve and run a corrected synthesis and second audit. FundedStudyRunner
ends immediately as limited, even with only 12 calls and less than one second of
synthetic elapsed time. Its ProviderRequest construction at study_runner.py:463
also does not populate the production claim-version context. The study is a
legitimate separate fixed-evidence experiment, but its result cannot establish
accuracy, cost or latency of the current production protocol without a parity
contract and explicit qualification.
Validation: probe.py::study_failed_audit uses existing synthetic approval fixtures
and injected HTTP mocks. Trace: 3 proposal, 3 critique, 1 evidence_review, 3
revision, 1 synthesis, 1 audit; final status limited; no correction/re-audit.
Fix direction: share a versioned transition policy with the production runner,
freeze that policy hash in study configuration, and test protocol traces across
both runners. If deliberately evaluating an ablation, label the omitted stages.

EVAL-03 [P2, process completeness] Prior visual blockers need not receive a
regression disposition in a later complete review.
Source: backend/src/round_robin/visual/reviews.py:62-84;
visual/service.py:293-317; visual/schemas.py:71-94.
Trigger: a parent has a critical finding; two child critics return empty findings.
validate_critique checks only that supplied previous_finding_id values are valid;
it does not require coverage of known prior findings. Both reviews are accepted,
and review coverage is complete with no pending-recheck limitation. No server
matrix carries unresolved blockers forward if a model omits them. Parent history
is retained, and coverage.complete does not itself claim quality; the defect is
the absent separate regression-completeness contract, not deletion of history.
Validation: probe.py::missing_regression_dispositions reproduces acceptance with
a known prior critical ID and two empty child critiques.
Fix direction: derive pending rechecks from material/critical parent findings and
locked requirements on the server. Require explicit resolved/persistent/regressed/
uncertain/declined dispositions or retain an unresolved marker. Keep pixel-review
quorum, regression completeness and quality decision separate.

EVAL-04 [P2, evaluation integrity] Renamed copies inflate the 48-task release
denominator.
Source: experiments/release.py:32-38; analogous exact-hash-only duplicate checking
in experiments/visual_evaluation.py:54-55.
Trigger: submit 48 briefs with identical question, options and evidence, changing
only the title of a valid DraftBrief and assigning required stratum labels. validate_manifest accepts
them because complete JSON hashes differ. summarize reports 48 independent primary
tasks and can meet the numerical target from one substantive case. The separate
phase_5_passed flag correctly stays false. FrozenStudyManifest has stronger alias
normalization at study_runner.py:110-123, but release manifests do not reuse it.
Validation: probe.py::aliased_release_cases reports one substantive case as 48
independent useful primaries with numerical_usefulness_target=true.
Fix direction: bind normalized substantive-case fingerprints, development-case
fingerprints and explicit provenance/stratum review; reject known aliases. Human
review is still required for semantic independence beyond exact normalization.

DESIGN LIMITATIONS, NOT ADDITIONAL CONFIRMED BUGS

* summarize_workflow counts primary usefulness against 13/16 and separately
  preserves repeat defects/completeness. It computes no paired benefit versus the
  strong baseline, uncertainty interval, reviewer agreement or per-stratum effect.
  A numerical threshold is descriptive; the code correctly keeps phase_passed
  false and benefit/protocol decisions pending. Add preregistered paired task-level
  comparisons, uncertainty and variability analyses before choosing the protocol.
* All three text arms use the same provider request schema, evidence and budget
  envelope. The single-provider arm includes synthesis and self-audit, which is a
  stronger comparator than a one-shot answer. However, additional agents and
  additional computation are changed together (healthy mock call counts 3/5/12).
  That tests the product packages; it does not isolate the causal value of debate
  from extra inference. A matched-compute ablation would address that question.
* Provider/name redaction and tokenized reviewer packets preserve identity maps,
  but text structure and number of linked assertions can reveal arms. The code
  explicitly requires human indirect-identity inspection; it does not implement
  or attest that inspection. Reviewer IDs establish distinct labels, not social
  independence or domain competence.
* Model/provider diversity is an operational independence measure, not a proof of
  independent errors. Pixel receipts establish bytes sent, not understanding.
* The supplied fictional fixtures and MockHTTP tests establish control behavior,
  not real-world correctness or human preference. README and all evaluation
  summaries retain their pending real-provider/human-release gates.

ALGORITHM/PROCESS INVENTORY AND ASSESSMENT

01. Synthetic adapter contracts (experiments/adapters.py:17-125): reject provider
credentials in offline mode; failure classification; two-call retry eligibility;
bounded canonical packets; no peer proposals in proposal packets; reference and
numeric shape validation. Appropriate deterministic controls, no truth validation.
Packet work O(bytes); reference checks O(references).

02. Journal append/recovery (experiments/journal.py:27-206): exclusive operator
flock; canonical hash chain; immutable manifest; durable file/head and directory
fsync; partial writes or mismatching head fail closed. Hashes detect corruption,
not a hostile operator rewriting history. Startup O(events + bytes); append O(new
event bytes), plus filesystem durability costs. Covered by runner tests.

03. Journal budget reducer (experiments/runner.py:30-334): Decimal arithmetic;
event replay; immutable run/attempt IDs; unresolved exposure carryover; owner and
deployment limits; two finishing holds; call/time reserves; settlement and explicit
reconciliation. Unknown attempts do not become free retries. Full replay O(events)
per state reconstruction; exposure scans O(runs * attempts), repeated for six
limit scopes. Bound batch sizes make this workable, but long-lived aggregate
journals should gain verified checkpoints/indexes before scale grows.

04. Dataset and trial planning (experiments/evaluation.py:39-114;
study_runner.py:56-129,364-375): stable canonical fingerprints; exact 16-task
strata; fixed 5-task repeats; double-review allocation; prospective snapshot
checking; normalized substantive duplicate check for frozen text study; randomized
primary executions precede repeats. Plan O(tasks * arms * repeats). No repeat
inflation of primary denominator. Keep the semantic-independence human gate.

05. Blinding and identity binding (experiments/evaluation.py:117-219): unique
original execution/output retention; common-provider redaction; opaque reproducible
packet IDs; separate private mapping; hash-bound output/configuration; private
durable immutable files. O(output bytes + outputs log outputs). Direct metadata
leakage is constrained; indirect blinding requires actual human inspection.

06. Manual grading/adjudication (experiments/evaluation.py:222-393): typed useful
scores; critical-defect disqualification; original grades retained; duplicate
reviewer-slot rejection; exact task/output binding; adjudications reference all
originals and follow their timestamps; missing/failed outputs remain denominator;
suspected critical defects require a second original. Work O(trials + grades).
No automatic phase pass. Missing paired efficacy/uncertainty analysis is explicit.

07. Timing estimator (experiments/evaluation.py:396-435): all admitted trials form
denominator; qualifying completed work required; missing/failed runs remain failures;
first-useful time cannot follow completion; successful-only nearest-rank median
and p90 labeled separately. O(n log n). This is conservative for incomplete runs;
it is not an unrestricted measure of first partial content.

08. Funded admission/configuration freeze (study_runner.py:132-362): expiration,
explicit funding and recipients; file hash binding; discovery/baseline/reviewer
record prerequisites; one aggregate spending policy; shared/exclusive lock around
operator policy; original run IDs survive new batches; durable attempt records.
These validate supplied records' structure and bindings, not actual observation.

09. Three-arm workflow (study_runner.py:378-642): independent proposal barrier;
optional parallel critiques; evidence review; dissent/critical-triggered revisions;
synthesis; different-provider audit except same-provider baseline; two bounded
attempts; retry-after/deadline checks; no replay after interrupted execution;
failures and unknown usage retained. EVAL-02. Claims context differs from runtime.
No majority-vote truth rule. Maximum 24 calls/run in shared journal policy.

10. Held-out release counting (experiments/release.py:19-103): exact 48-task
strata; immutable configuration/protocol ID; prospective timestamps; original
review identities; critical defect double-review; conservative minimum scores and
reasoned adjudication; 39/48 numerical target; no automatic release. EVAL-04.
O(tasks + grades + serialized brief bytes).

11. Visual study (experiments/visual_evaluation.py:22-237): >=12 matched briefs;
4 fixed repeats; shared initial-image hashes across arms; baseline cannot replace
its initial image; blinded pixel packet binding; two-review allocation; adverse
repeats retained; exact unknown-exposure cost accounting; paired cost/time deltas;
limits reported; no automatic release. Exact-hash brief independence is weaker
than normalized text study checks. No paired human efficacy estimator is supplied.

12. Visual pixel-review protocol (visual/reviews.py:11-84): canonical pixels and
server-created receipts; equal fixed candidate; actual view-byte hash verification;
parent pixels bound for comparison; no current peer critiques in initial packets;
version/provider/receipt checks; two eligible non-generator providers for quorum;
unknown provenance disclosed. Receipt work O(pixel bytes), critique checks
O(findings). EVAL-03. Two-provider agreement is not a correctness proof.

13. Visual state/resource reducer (visual/iterations.py:19-146): exact finite
money; defensive copy of persisted nested state; journal/counter consistency;
mode/fence/epoch checks; 1800-second original lifetime; protected review time/money/
calls; 24 calls, 4 image submissions, 60 polls, 3 versions, 2 edits, 6 render
attempts; conflicting settlements rejected; cancellation increments fence.
O(operations), with explicit small bounds. No quality-based automatic edit stop.

14. Image job identity/recovery (visual/jobs.py:12-90): recursively hash request
bytes; require immutable authorization identity; persist possibly-sent state before
external call; no blind retry; capability-gated same-job lookup; counted polls and
fence/epoch validation. Current implemented HTTP image endpoint is synchronous;
helpers do not fabricate asynchronous support. O(packet bytes).

15. Visual schemas (visual/schemas.py:11-115): bounded dimensions/pixel product;
typed mode and revisions; bounded findings; geometry within delivered view;
response-local alias uniqueness; explicit capability flags and honest async
constraints. EVAL-03: missing relation between prior finding and required status.

16. Visual scheduling/persistence/lineage (visual/service.py:150-344): immutable
latest-parent check; counted authorization before generated publication; independent
critic scheduling with per-step limits; scoped server finding IDs; one review per
provider/version; coverage distinct from user selection; retained history; current
round review contents not merged into peers. EVAL-01/EVAL-03 at packet boundaries.

17. Visual artifact resource/recovery (visual/service.py:24-149,237-285,345-483):
owner/deployment storage holds; private path/hash ownership; immutable native source
metadata; expired local holds reaped; cancellation/deletion/restoration fences;
unknown spending retained; validated backup/restore rebase. Storage accounting
scans all designs, versions and operations per reservation, O(D+V+O). These protect
discussion artifacts; they do not establish visual correctness.

18. Edit and re-review communication (api/visual.py:340-385;
worker/image_tasks.py:218-251; providers/images.py:243-327): edit from exact latest
parent requires previous two-critic coverage; chosen IDs validated; user intent
sent; edited pixels and shared prior findings sent to critics; structured response
parsed and server-bound. EVAL-01: choices/actual findings omitted from generator.
