# Native renderer container security review

The repaired image retains **40 open OS package/advisory matches across 27 CVEs: 34 MEDIUM and 6 LOW by Ubuntu's vendor ratings**. No fixed Ubuntu package version was reported for these matches. All indexed fixable findings were removed from the final inventory, but this is **not** an all-vulnerabilities-cleared result. The 40 exact remaining package/CVE rows and their vendor status appear below; no findings were suppressed.

The locally built and tested image is `sha256:c6f3ab5af89edfb2459e75ad47a89972466747e780151fff4b280570aac4df1b`. Both `round-robin-native-renderer:exhaustive-audit` and `round-robin-native-renderer:local` point to that ID. All original/alternative scan, build, test and provenance artifacts were retained. After Docker VM disk exhaustion interrupted a later PostgreSQL verification run, the root reviewer removed only the audit-created obsolete original/candidate/alternative images to recover space; the final tested image and its tags remain. Nothing was deployed.

Counts are package/advisory matches, so one CVE can affect several binary packages. Severity counts come from each distribution's selected feed and are not normalized cross-vendor exploitability scores. Some remaining Ubuntu MEDIUM findings have higher upstream scores, including libXrender's malicious-X-server heap overflow. The comparison does not establish that the final image is vulnerability-free. [Ubuntu libXrender advisory](https://ubuntu.com/security/CVE-2026-88807)

The multistage Dockerfile preserves the exact pinned Playwright Chromium headless shell and Node binaries, then installs only the official supported Ubuntu 26.04 Chromium dependencies/fonts with available apt upgrades. It excludes other browsers, GStreamer/media packages and build-time npm dependency trees. Original HIGH GStreamer matches were CVE-2025-3887; Ubuntu Noble's published fix is an ESM package, so a normal apt upgrade was not described as fixing it. The affected packages are absent from the new runtime. An unused, non-dpkg-owned `/usr/bin/pebble` binary was removed after the candidate scan found its fixable Go stdlib advisory. Normal dpkg/package metadata remains intact. [Ubuntu GStreamer advisory](https://ubuntu.com/security/CVE-2025-3887)

The supported Debian 13 alternative was built and passed the same seven native tests; its actual advisory inventory was materially worse, so Ubuntu 26.04 was retained. This assessment did not use unsupported distribution combinations, strip package metadata, hide findings or invent security backports. Installed Playwright 1.65.1 dependency tables were inspected for explicit Ubuntu 26.04 and Debian 13 support.

The final image passed **7 actual native integration tests in 13.16 seconds**. The added runtime invariant checks nonroot UID, only the Chromium headless browser, absent npm/build tools/media/Pebble, retained package metadata, and the SHA-256 of `/opt/renderer/native-renderer.mjs` against the current repository source. Actual execution was on linux/arm64; amd64 was not run.

The enforced renderer profile uses no network, a readonly root filesystem, UID/GID 10001, no capabilities or new privileges, no host mounts/operator environment, private bounded tmpfs, one CPU, 512 MiB memory, 128 PIDs, and bounded input/output/deadlines. These controls constrain impact; they do not prove a vulnerable parser is unreachable. Rebuild/retest/rescan when supported vendor fixes become available. Every row below remains **OPEN**.

## Compact upstream release/advisory check

The official Node distribution index lists **26.13.1 as the latest 26.x release** and marks it as a security release. Its November 11 release/security notes describe fixes for the current TLS, HTTPS and HTTP/2 advisories; no newer 26.x release or later security-index post was observed. The distribution index itself dates the entry November 10, while the blog dates it November 11; that provenance difference is retained in JSON. [Node release](https://nodejs.org/en/blog/release/v26.13.1), [Node security notice](https://nodejs.org/en/blog/vulnerability/november-2026-security-releases), [distribution index](https://nodejs.org/dist/index.json)

The official Playwright latest-release API reports **1.65.1**, published November 13, bundling Chromium **159.0.8154.6**. The repository's public advisory endpoint returned no entries; this is not a comprehensive product advisory database. Google's November 16 Chrome for Testing feed lists this exact browser as current **Beta**, not Stable. Dev/Canary160 builds are separate channels. [Playwright release](https://github.com/microsoft/playwright/releases/tag/v1.65.1), [repository advisories](https://github.com/microsoft/playwright/security/advisories), [Google channel feed](https://googlechromelabs.github.io/chrome-for-testing/last-known-good-versions.json)

The latest stable security posts were also reviewed, including the November 9 XML flaw reported as actively exploited and the additional November 11 fixes. Those stable-channel posts do not independently prove every fix present or absent in the bundled159 Beta binary. This compact check established no concrete required newer patch for the exact installed versions; it does **not** clear the standalone-binary or cross-branch patch-coverage limitation. Retrieved primary-source bytes, URLs and SHA-256 hashes are preserved in the JSON evidence. No source/test/configuration input changed. [November 9 security update](https://chromereleases.googleblog.com/2026/11/stable-channel-update-for-desktop_018223192.html), [November 11 security update](https://chromereleases.googleblog.com/2026/11/stable-channel-update-for-desktop_01744469280.html)
