# Independent verification-tool review

The evidence reviewer read the current `scripts/coverage_gate.py`, `scripts/audit.py`, `.coveragerc`, their tests, and the verification/native-capture command contracts independently after the application review. This review used current code and fresh diagnostics only.

Findings fixed:

- The manifest bound executable files but omitted tests, dependency locks, configuration, generated API contracts/types, renderer Dockerfiles, fixture data, styles and JavaScript instrumentation. `input_files()` now hashes these separately as `verification_inputs`; changes, additions and removals invalidate the result. Docs, results, caches and generated build intermediates are excluded from this input inventory. Executable targets and coverage denominators were not removed or reduced.
- Nested malformed JSON could escape the CLI's error handler and leave an old successful result in place. Mapping/list/count validation now rejects malformed shapes; the CLI writes a sanitized failed report over stale success.
- Duplicate normalized paths silently overwrote report entries, while duplicate or intersecting executed/missing arrays could inflate counts. Normalize and reject path collisions; require unique typed locations and disjoint covered/missing/excluded sets.
- Runner lock, capture cleanup, subprocess launch or artifact-copy errors could leave no durable failed record. Create an incomplete/failed record before setup, sanitize exceptions and keep the result failed on cleanup error or interruption.
- Child zero exit codes alone could declare success without affirmative final records. Require current verification and coverage JSON with explicit success and both source/input attestations, then copy current capture summaries. Reject symlink capture paths and outputs within directories the runner will clear. Retain the exclusive lock and fresh output-directory rule.
- Default standalone coverage output still used an obsolete audit location. Moved it to `.local/coverage`; the fresh wrapper continues to supply its isolated `COVERAGE_FILE`.
