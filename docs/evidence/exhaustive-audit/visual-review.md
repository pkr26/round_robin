# Fresh visual, frontend and native renderer audit

This review began from current implementation and product invariants in this audit session. Previous audit reports and historical coverage were not used as findings or as the starting point. The companion `visual-review.json` records reviewed files and their current SHA-256 hashes. Coverage below is diagnostic; final acceptance requires the root verifier's clean, source-bound full run.

## Independent passes

1. Read the visual storage, schemas, receipts, review quorum, iteration ledger, persisted operation workflow, HTTP routes, image adapters, native subprocess boundary and renderer source. Derived invariants: exact owner/session/version scope; immutable pixels and sources; explicit recipient/price authorization before sends; no invented reviewer provenance; independent critics; retained uncertain exposure; finite requests, bytes, clock and storage; private durable files; safe interruption and recovery.
2. Challenged those invariants with malformed images, compressed error responses, forged hashes/receipts, hostile paths, symlink ancestors, FIFO files, failed fsync and thread startup, partial writes, stale fences, failed DB publication, changed Decimal contexts, invalid configurations, duplicate work, unavailable critics, failed/unknown receipts and cancellation. HTTP transports and providers were synthetic; subprocess stream tests use real local processes. The native JavaScript harness executes the original production source with instrumented counters and controlled browser/stdio imports.
3. Read the API client and design/live UI state transitions, testing access changes during asynchronous hashing, reads and downloads; command replay ambiguity; private browser storage; native source/local edit races; monotone polling; original artifact identity; quote expiry and explicit parent replacement/reuse. A separate evidence reviewer read the full sample workspace and challenged fictional provenance, persistence, expiry, partial results and exports. The root reviewer independently exercised live UI state and error paths. A later read-only cross-review validated the generated live fixture against current MeetingView and Snapshot contracts and identified weak post-unmount assertions; root strengthened these to resolve old parent/run/meeting responses while a different scope remains mounted (73 unit tests pass).
4. Independently reviewed hosted callback and response-policy boundaries plus export read revocation. Found the global hosted CSP overwrite and unbounded pending login-state accumulation; root/evidence owners fixed and tested them. A subsequent filesystem pass found an ancestor-link bypass in orphan cleanup and replaced existing private-source/backup reads with bounded regular-file opens.
5. Ran a fresh isolated comparison against the source snapshot taken at the beginning of this session. Nine selected regressions failed against that original source for their intended decoder, symlink, forged-hash, cross-owner purge and Decimal assertions. The current equivalents pass. No shared production files were replaced for the replay; logs are under `.local/exhaustive-audit/visual/before-replay/`.

## Final connected regression addition

`tests/e2e/fresh_reuse.spec.ts` adds one real connected journey: actual simulated parent completion through the API/workers; saved-history UI reopening; explicit selection of one unchecked parent source; quote refresh; explicit child Start and worker completion. It checks that exactly one imported source retains the parent origin, bytes, hash and timestamp with a fresh child identity and downgraded `not_checked` status, excludes every original parent ID, and preserves the parent run, brief, report and evidence. Matching a hash alone cannot pass this test because freshly entered child facts may share bytes. The test creates and deletes only its own comparison and refuses external hosts. Playwright discovery passed; execution passed in the root final-accepted run (29 total browser tests). That run later stopped on the intermittent design unit test described below, so it is not overall final acceptance.

## Native source ordering follow-up

The first final-accepted run passed the real services, all 29 browser journeys (including the new connected reuse journey), and actual native sandbox tests, but its frontend unit stage exposed a design-source edit overwrite. The earlier test addressed a hidden control and did not establish that source hydration had begun or that the reopen action had released the editor. Strengthening only those preconditions would leave an early-effect ordering untested. A deterministic test now defers only the selected native hydration effect while keeping actual React state and DOM events, opens the source details, verifies visible/enabled input and an established local edit, starts the pending effect and resolves its read. Before the production fix, that early-effect case failed with saved text replacing the edit; the ordinary in-flight case passed. The scope-transition baseline fix makes both pass. All **205 frontend tests** then passed under raw-source instrumentation, and `pnpm typecheck` passed. The root must rerun clean acceptance because the application source changed.

## Audit runner interruption cross-review

Independently read the runtime reviewer's final `scripts/audit.py` process ownership and `backend/tests/test_exhaustive_audit_runner.py` regressions. No additional concrete defect was found. New commands own a new process group; interrupts during spawn are deferred until ownership is known without imposing an inherited blocked signal mask. Cleanup resists repeated interruption, grants the verifier a graceful cleanup interval, then bounds TERM/KILL escalation. It reaps the launcher, checks surviving descendants, rejects launcher-only success and publishes the final failed record before closing the capture lock.

The first review identified that mocked escalation/early-exit tests did not establish operating-system group behavior. Runtime added real process tests: both SIGINT/SIGTERM against the runner, a blocked grandchild proving the capture lock remains held, repeated interrupts, an unrelated sentinel that survives, SIGINT-ignoring launcher/grandchild forcing TERM, an uncooperative process forcing KILL and reaping, and a zero-exit launcher with a live child that is rejected and cleaned. Runtime reports all **49 runner tests pass**. This reviewer inspected the actual code and assertions; runtime owns execution logs and final verifier integration. No runner input was edited by this reviewer.

## Limits

Execution coverage does not establish absence of vulnerabilities, complete race-interleaving exploration, actual provider billing or useful visual critique. SQLite/synthetic adapters cannot substitute for PostgreSQL concurrency and real browser/container isolation tests. Local filesystem protection assumes the configured private artifact directory is not writable by a hostile operating-system peer; final-component no-follow checks and ancestor validation do not claim a kernel-enforced directory-handle sandbox. No paid request, production deployment, public upload or user-data transfer was performed. The final report must cite the clean full verifier and strict per-service gate, not these intermediate percentages alone.
